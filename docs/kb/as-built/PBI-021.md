## Rules

- Decision tables evaluated or seeded: none (field operators reuse `conditionOperatorSchema` from the rules-engine set; no new DT rows)
- Entitlements / `authorize()`: `screener:run`, `screener:list`, `screener:save`, `screener:delete`; add-to-watchlist uses `watchlist:item:create` + `audit_log`. `runScreenerAction` requires a session JWT and calls `POST /functions/screener` with that user token (no service-role key in the browser or Next action). The edge function re-checks JWT + `authorize('screener:run')`, compiles criteria (fail-closed), then `createAdminClient` RPCs `exec_screener` (`EXECUTE` granted to `project_admin` only). Screens are owner RLS (`auth.uid()`). `instrument_daily_rsi` is SELECT for `anon`/`authenticated` and writes for `project_admin`. RSI refresh (`analytics-service` `op: "rsi"` / snapshot) is service bearer `API_KEY` / `INSFORGE_API_KEY` only.

## Residual (non-blocking)

- `exec_screener` still `EXECUTE`s a SQL string. Harmless while the only caller is the edge function after `compileScreenerSql` (Zod + identifier whitelist + `assertSafeScreenerSql`); a compiler bypass would be dynamic SQL. Function-level keyword guards remain. `instrument_daily_rsi` SELECT is public (`USING (true)`); the app JWT-gates screener runs.

## How to extend

- Register a new screenable column only in `SCREENER_FIELD_REGISTRY` (SQL expression whitelist) + `screenerFieldIdSchema`; never concatenate user strings into SQL
- Copilot `screen_instruments` should call the same `compileScreenerSql` / `screener` function
- Do not fork a second fundamentals metrics shape; P/E, yield, and 52w proximity read `fundamentals.metrics` groups from PBI-020
- Rebuild `pnpm functions:bundle:screener` and `pnpm functions:bundle:analytics-service` after service changes
