| Spec intent | done |
| Notes | Pure `evaluate(table, context, clock)` + `compile(table)` in `@meridian/rules-engine`. Zod table/row types live in `@meridian/schemas` and are re-exported from the engine. Condition cells may set `negate` so doc 05 prose such as “not between” can be encoded without a new operator. Field-vs-field comparisons (e.g. notional vs buying power) are facts the caller prepares; the engine compares `context[input]` to a cell `value`. ## Rules

- Decision tables evaluated or seeded: fixture encodings of DT-RISK-01, DT-VAL-01, DT-VAL-02 (trail row), DT-FEE-01, DT-ENT-01 for unit vectors only — not published
- Entitlements / `authorize()`: unchanged bootstrap helper (not DT-ENT-01 evaluation)

## How to extend

- PBI-011 should load published tables, inject `clock`, call `evaluate` or `compile`, and persist `trace` / `matchedRows` / `outcome` to `rule_audit`
- Add operators only by extending `conditionOperatorSchema` and `matchOperator` together
- Do not put policy literals in application code; put them in table rows
- Do not fork a second evaluator in edge functions
